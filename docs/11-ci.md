# GitHub Actions Build

## 1. 실행 조건

`.github/workflows/build.yml`은 다음 Git 이벤트에서 실행됩니다.

- 모든 branch의 `push`
- 모든 branch 대상 `pull_request`

배포, 이미지 게시와 외부 환경 변경은 수행하지 않습니다.

## 2. 검증 단계

```text
Checkout
  → Temurin Java 21
    → Gradle Wrapper 검증과 캐시 복원
      → ./gradlew test --no-daemon
        → ./gradlew performanceTest --no-daemon
          → 표준·성능 테스트 결과 artifact 업로드
```

`gradle/actions/setup-gradle`이 Gradle User Home 캐시와 Wrapper checksum 검증을 함께 담당합니다.
별도 cache action과 Wrapper validation job을 중복 구성하지 않습니다.

Ubuntu GitHub-hosted runner에서 Docker를 사용할 수 있으므로 PostgreSQL Testcontainers 기반 Repository
테스트도 실제 실행 대상입니다. Docker를 찾지 못하면 해당 테스트가 skip되는 정책은 로컬과 동일합니다.

## 3. 테스트 결과

성공 여부와 관계없이 다음 경로를 `gradle-test-results` artifact로 7일간 보존합니다.

```text
build/test-results/test
build/reports/tests/test
build/test-results/performanceTest
build/reports/tests/performanceTest
```

XML은 자동 분석에, HTML 보고서는 사람이 실패 원인을 확인할 때 사용합니다.

## 4. 로컬 재현

CI와 같은 Java 21 환경에서 다음 명령을 실행합니다.

```powershell
.\gradlew.bat test --no-daemon
```

Linux와 macOS에서는 다음 명령을 사용합니다.

```bash
./gradlew test --no-daemon
```

CI의 Testcontainers 검증까지 동일하게 재현하려면 Docker daemon이 실행 중이어야 합니다.

## 5. 권한과 제한

- Workflow 기본 권한은 `contents: read`입니다.
- secret, 배포 권한과 패키지 쓰기 권한을 요구하지 않습니다.
- Job 제한시간은 15분입니다.
- 성능 기준선은 일반 테스트와 다른 Gradle 작업으로 실행해 실패 위치와 보고서를 분리합니다.
