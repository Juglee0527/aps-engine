# Capacity Planning

## 1. 현재 범위

현재 CAPA 단계는 설비별 반복 주간 근무시간을 기준으로 기간 가용시간을 계산하고,
저장된 스케줄의 작업 부하와 결합해 사용률과 병목 후보를 진단합니다.

```text
Machine
  → Weekly Working Calendar
    → Machine Maintenance 차감
      → 요청 기간의 실제 가용 구간
      → 총 가용 분
        → ScheduledOperation 가공 분 + Changeover 분
          → 계획기간 CAPA 사용률
```

## 2. WorkingCalendar 규칙

- 요일과 시작·종료시각으로 반복 주간 근무시간을 정의합니다.
- 종료시각은 시작시각보다 이후여야 합니다.
- 자정을 넘는 시간대는 첫 MVP에서 허용하지 않습니다.
- 같은 설비와 요일의 시간대는 서로 겹칠 수 없습니다.
- `INACTIVE` 설비에는 신규 캘린더를 등록할 수 없습니다.

## 3. 가용시간 계산

`WorkingTimeCalculator`는 주간 규칙과 요청의 고정 UTC offset을 사용합니다.

- 조회 구간 밖의 근무시간은 경계에서 잘라냅니다.
- 여러 근무일에 걸친 총 가용 분을 합산합니다.
- 활성 계획 정비와 겹치는 근무시간을 실제 가용 구간에서 제외합니다.
- 정비가 근무시간 밖에 있거나 경계에만 맞닿으면 가용 분은 줄어들지 않습니다.
- 작업시간이 하루 근무시간을 넘으면 다음 근무일로 이어서 종료시각을 계산합니다.
- 주말, 비근무시간과 정비시간은 작업시간에 포함하지 않습니다.
- 무한 탐색을 방지하기 위해 최대 10년까지만 작업 배정을 탐색합니다.

## 4. 계획 부하와 사용률

APS Engine은 ScheduleRun의 설비별 부하를 다음 식으로 계산합니다.

```text
설비 부하(분) = 해당 설비 (workingMinutes + changeoverMinutes) 합계
CAPA 사용률(%) = 설비 부하 ÷ 계획기간 가용 분 × 100
```

## 5. 병목 진단 규칙

- 가용 분이 0이고 부하가 있으면 `NO_AVAILABLE_CAPACITY`로 최우선 판정합니다.
- 가용 분이 있는 설비는 사용률 80% 이상을 후보로 판정합니다.
- 사용률 100% 초과는 `CAPACITY_EXCEEDED`, 나머지는 `HIGH_UTILIZATION`입니다.
- 가용 분과 부하가 모두 0인 설비는 후보가 아닙니다.
- 정렬은 가용 CAPA 없음, 사용률 내림차순, 설비 코드와 ID 오름차순입니다.
- 표시 사용률은 소수 둘째 자리로 반올림하지만 판정과 정렬은 반올림 전 비율을 사용합니다.

이는 CAPA 위험을 찾는 설명 가능한 진단 규칙입니다. 생산오더나 설비를 자동 재배치하지 않으며,
최적화 알고리즘의 결과도 아닙니다.

## 6. 시간대와 제외 범위

첫 구현은 한국 표준시처럼 DST 변경이 없는 고정 offset 사용을 전제로 합니다.
ScheduleRun의 `planningOffsetSeconds`를 CAPA 조회에 다시 사용해 DB가 UTC instant를 반환해도
근무시간을 실행 당시 공장 현지시각으로 계산합니다.
지역별 DST가 필요한 시점에는 `ZoneId` 기반 캘린더로 확장해야 합니다.

공휴일, 비정기 휴게시간 예외와 교대조 캘린더는 아직 포함하지 않습니다.
