# APS 학습 가이드 개편 명세

## 1. 목적

APS Engine은 기능 시연용 화면에 머무르지 않고, APS를 처음 공부하는 사용자가 개념을 익히고
직접 계획을 실행하며 결과를 해석할 수 있는 학습용 애플리케이션을 목표로 합니다.

사용자는 가이드를 마친 뒤 다음 질문에 답할 수 있어야 합니다.

- APS가 어떤 입력을 받아 어떤 결과를 만드는가?
- ERP·MRP·MES와 APS의 역할은 어떻게 다른가?
- 생산오더, Routing, Operation, 설비와 CAPA는 어떻게 연결되는가?
- 유한능력 계획에서 작업이 왜 특정 설비와 시각에 배정되는가?
- Priority, EDD, SPT는 어떤 계획 차이를 만드는가?
- 납기 지연, Makespan, Lead Time, 설비 가동률과 병목을 어떻게 해석하는가?
- Changeover, Maintenance, 대체 설비와 Frozen Horizon이 계획에 어떤 영향을 주는가?

## 2. 학습 원칙

모든 실습은 다음 순서를 따릅니다.

```text
개념 설명 → 결과 예상 → 시나리오 준비 → 실행 → 결과 관찰 → APS 관점 해설 → 후속 실험
```

- 긴 이론을 먼저 읽게 하지 않고 짧은 설명 직후 직접 실행하게 합니다.
- 무작위 데이터 대신 학습할 현상이 명확히 나타나는 결정론적 데이터를 사용합니다.
- 화면의 지표에는 계산 의미와 확인할 질문을 함께 제공합니다.
- 학습 데이터는 사용자가 직접 만든 데이터와 구분하고 반복 실행할 수 있게 합니다.
- 비교 실습은 원본 오더와 확정 계획을 변경하지 않는 미리보기 계산을 우선합니다.
- 학습 편의 기능을 핵심 스케줄링 도메인 규칙과 분리합니다.

## 3. APS의 위치

이 프로젝트에서 APS는 생산 요구를 실행 가능한 상세 시간표로 변환합니다.

```text
생산오더 + Routing + 설비 + 근무시간 + 제조 제약
                         ↓
                  APS 스케줄 엔진
                         ↓
작업 순서 + 설비 배정 + 시작·종료시각 + 납기 위험 + 병목 후보
```

| 시스템 | 중심 질문 | 이 프로젝트의 범위 |
| --- | --- | --- |
| ERP | 무엇을 사고 팔고 회계 처리하는가? | 범위 밖 |
| MRP | 무엇을 언제 얼마나 조달·생산해야 하는가? | BOM·재고·자재 가용성은 범위 밖 |
| APS | 제한된 자원으로 무엇을 언제 어디서 만들 것인가? | 핵심 학습 범위 |
| MES | 현장에서 실제로 무엇이 진행되고 있는가? | 실시간 설비 수집은 범위 밖 |

APS 결과는 하나의 절대적인 정답이 아닙니다. 선택한 우선순위 규칙과 입력 기준정보에 따른 실행 가능한
계획 후보이며, 사용자는 KPI와 현장 조건을 함께 검토해야 합니다.

## 4. 학습 과정

### 과정 A. APS 시작하기

1. APS가 답하는 세 질문: 무엇을 먼저, 어디에서 언제, 어디가 위험한가
2. 기준정보와 계획 데이터 구분
3. 첫 생산계획 생성
4. 간트와 생산오더 상태 읽기

### 과정 B. 유한 CAPA 이해하기

1. 설비 근무시간과 가용시간
2. 공정 선후관계와 오더 투입 가능시각
3. 설비 대기와 공정 대기
4. Lead Time과 Makespan

### 과정 C. 배차 규칙 비교하기

1. 명시적 우선순위
2. EDD
3. SPT
4. 같은 입력의 작업 순서와 KPI 비교

### 과정 D. 제조 제약 실험하기

1. 방향성 Changeover
2. 계획 정비시간
3. Operation 대체 설비
4. 설비 부하와 병목

### 과정 E. 계획 변경 대응하기

1. 긴급오더 추가
2. Frozen Horizon 설정
3. 고정·이동·신규 작업 구분
4. 재스케줄링 전후 KPI 비교

### 과정 F. 운영과 성능 이해하기

1. CSV 대량 입력과 검증
2. 비동기 실행 상태와 실패 이력
3. 중규모 계획 탐색
4. 실행시간과 입력·출력 규모 관찰

## 5. 학습 시나리오 카탈로그

| 키 | 데이터 규모 | 의도된 관찰 결과 |
| --- | --- | --- |
| `FIRST_PLAN` | 2설비·2품목·4오더 | 기준정보에서 실행 계획까지 전체 흐름 |
| `FINITE_CAPACITY` | 1설비·1품목·4오더 | 유한 CAPA, 비근무시간과 대기 |
| `PRECEDENCE` | 3설비·1품목·2오더 | 가공→검사→포장 공정 선후관계 |
| `TARDINESS` | 1설비·2품목·4오더 | 납기 지연과 지연 KPI 읽기 |
| `RULE_COMPARISON` | 1설비·3품목·6오더 | Priority·EDD·SPT의 순서와 KPI 차이 |
| `BOTTLENECK` | 3설비·1품목·4오더 | 특정 공정의 높은 가동률과 대기 누적 |
| `CHANGEOVER` | 1설비·2품목·4오더 | 품목 순서에 따른 준비시간 변화 |
| `ALTERNATIVE_MACHINE` | 2설비·1품목·3오더 | 후보 설비의 가장 이른 완료시각 선택 |
| `MAINTENANCE` | 1설비·1품목·3오더 | 정비 구간 회피와 일정 이동 |
| `FROZEN_HORIZON` | 1설비·기존 3오더+긴급 1오더 | 고정·이동·제외·신규 작업과 미래 작업 재배치 |
| `MEDIUM_FACTORY` | 12설비·150오더 | 필터·검색을 사용한 계획 탐색 |
| `PERFORMANCE` | 20설비·600오더 | 실행시간과 관측성 확인 |

성능 시나리오는 모든 작업을 한 화면에 그리는 용도가 아닙니다. 요약 지표와 필터를 먼저 제공하고,
선택한 설비·기간·오더의 작업만 상세 렌더링합니다.

현재 결정론적 데이터는 `MEDIUM_FACTORY` 150오더와 `PERFORMANCE` 600오더로 고정합니다.
600오더는 한 품목당 한 Operation을 사용해 600작업을 만들며, 단위 테스트에서 5초 계산 기준을
넘지 않도록 감시합니다. 이 기준은 개발 환경 회귀 감지용이며 운영 SLA를 의미하지 않습니다.

## 6. 학습 시나리오 데이터 계약

학습 시나리오는 브라우저의 대형 JavaScript 상수로 관리하지 않습니다. 서버의 시나리오 정의가 상대
날짜를 실행 시점의 실제 날짜로 변환하고, 생성한 엔티티와 오더를 하나의 시나리오 인스턴스로 추적합니다.

- 같은 시나리오를 여러 번 실행해도 비즈니스 코드가 충돌하지 않아야 합니다.
- 시나리오별 오더만 선택해 계산할 수 있어야 합니다.
- 다른 시나리오와 사용자가 직접 등록한 `CONFIRMED` 오더를 포함하지 않아야 합니다.
- 시나리오 데이터 초기화는 해당 인스턴스가 생성한 데이터만 대상으로 합니다.
- 시나리오 생성과 초기화는 트랜잭션 경계를 갖고 부분 상태를 남기지 않습니다.
- 데이터 수량과 의도된 결과를 자동 테스트로 고정합니다.

## 7. 결과 해설 계약

각 실습은 다음 내용을 결과 화면에 제공합니다.

- 이번 실습에서 확인할 질문
- 실행 전에 예상한 결과
- 실제 작업 순서와 설비 선택
- 핵심 KPI와 이전 결과 대비 변화
- 결과가 나온 이유
- 입력 또는 제약 하나를 바꿔보는 후속 실험
- 현재 엔진이 고려하지 않는 현실 제약

해설은 단순히 “사용률이 85%입니다”라고 표시하지 않습니다. 어떤 부하와 가용시간으로 계산됐으며,
어떤 오더 또는 공정이 대기를 만들었는지 사용자가 추적할 수 있어야 합니다.

## 8. 구현 경계

### 포함

- 사용자 가이드 정보구조와 학습 과정
- 결정론적 학습 시나리오 생성·격리·초기화
- 동일 입력의 비파괴 Dispatching Rule 비교
- 제약조건과 Frozen Horizon 실습
- 중규모·성능 데이터 세트
- 검색·필터·페이지네이션과 선택 범위 간트
- 학습 진도와 결과 해설

### 제외

- 상용 APS 수준의 전역 최적화 Solver
- 수요예측, MRP, BOM과 자재 제약
- 실시간 MES 연동
- 사용자 계정 간 학습 진도 동기화
- 운영 환경에서 임의 데이터를 생성하는 범용 데이터 생성기

## 9. 완료 기준

- 빈 데이터베이스에서 첫 계획 실습을 중단 없이 완료할 수 있습니다.
- 모든 실습은 목적, 예상, 실행, 관찰, 해설을 제공합니다.
- 같은 입력의 Priority·EDD·SPT 결과를 원본 상태 변경 없이 비교할 수 있습니다.
- 시나리오 데이터가 다른 시나리오와 사용자 데이터를 오염시키지 않습니다.
- 150개 오더를 검색·필터하며 화면에서 탐색할 수 있습니다.
- 500개 이상 오더의 실행 결과를 요약 중심으로 확인할 수 있습니다.
- 시나리오 생성, 계획 범위, 규칙 비교와 핵심 UI 계약에 자동 테스트가 있습니다.
- README와 관련 설계 문서가 실제 동작과 일치합니다.
- 학습 인스턴스 전용 실행 API는 추적된 생산오더만 계획 범위로 사용합니다.
