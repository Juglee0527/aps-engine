# UI 현대화 계획

> 완료 상태: 2026년 8월 8일 `060~067` 구현·검증 및 `main` push 완료

## 목표

APS Engine의 UI를 단순한 기능 데모가 아니라, 생산계획 담당자가 정보를 빠르게 읽고
APS 학습자가 다음 행동을 자연스럽게 이해할 수 있는 학습형 Control Tower로 개선합니다.

프레임워크 도입 자체를 목표로 삼지 않습니다. 현재 화면 품질 문제는 Vanilla JavaScript보다
일관된 디자인 토큰, 정보 위계, 화면 상태 표현과 컴포넌트 규칙이 부족한 데서 더 크게
발생합니다. 우선 네이티브 ES Module 구조를 유지하면서 시각 체계와 사용성을 개선하고,
구현 후 복잡도와 유지보수 비용을 근거로 프레임워크 전환 여부를 다시 판단합니다.

## 현재 UI 진단

2026년 8월 8일 실제 로컬 화면과 정적 리소스를 기준으로 확인한 내용입니다.

- `index.html` 869줄, `styles.css` 455줄, `app.js` 1,159줄로 기능과 표현 책임이 큽니다.
- 본문과 표에 8~11px 글자가 많이 사용되어 한글 정보의 가독성이 떨어집니다.
- `body`의 `min-width: 1180px` 때문에 작은 노트북과 모바일에서 자연스러운 재배치가 어렵습니다.
- 카드, 패널, 버튼과 입력 요소가 대부분 같은 사각형과 비슷한 밀도로 표현되어 중요도 차이가 약합니다.
- 상단 작업 버튼이 화면 맥락과 충분히 분리되지 않아 현재 화면의 핵심 행동을 찾기 어렵습니다.
- 문자 기호 기반 아이콘과 영문 보조 문구가 제품 인상을 거칠게 만들고 의미 전달도 일관되지 않습니다.
- 로딩, 빈 상태, 오류, 성공과 비활성 상태가 시각적으로 충분히 구분되지 않습니다.
- 사용자 가이드는 내용은 풍부하지만 한 화면의 정보량이 많아 학습 순서와 현재 위치가 흐려집니다.

## 디자인 원칙

1. **읽기 우선**: 한글 본문은 최소 14px, 표와 보조 정보도 12px 이상을 기본으로 합니다.
2. **행동 우선순위**: 화면마다 대표 행동은 하나만 강하게 표시하고 나머지는 보조 단계로 낮춥니다.
3. **상태가 설명하는 화면**: 로딩, 빈 상태, 오류와 다음 행동을 같은 영역에서 이해할 수 있게 합니다.
4. **APS 정보 위계**: 계획 상태 → KPI → 간트 → 병목과 오더 상세 순으로 읽히게 합니다.
5. **학습과 운영의 연결**: 가이드에서 배운 개념이 스케줄 보드의 동일한 용어와 색으로 이어지게 합니다.
6. **점진적 구조 개선**: 빌드 도구 없이 CSS와 ES Module을 정리하되 교체 가능한 컴포넌트 경계를 만듭니다.
7. **반응형과 접근성 기본 제공**: 키보드, 포커스, 명도 대비, 축소 화면을 완료 조건에 포함합니다.

## 목표 화면 구조

```text
App Shell
├─ Sidebar / Mobile Navigation
├─ Context Header
│  ├─ 현재 화면 제목과 설명
│  └─ 화면별 대표 행동
└─ View
   ├─ 상태 또는 학습 맥락
   ├─ 핵심 KPI
   ├─ 주 작업 영역
   └─ 상세 탐색과 보조 정보
```

스케줄 보드는 계획 실행 상태와 병목 판단을 우선하고, 생산오더와 마스터 데이터는 검색·표·등록 흐름을
우선합니다. 사용자 가이드는 긴 대시보드가 아니라 과정 탐색, 개념 학습, 실습, 결과 해설의 단계형
레이아웃으로 분리합니다.

## 구현 로드맵

### 060. UI 기반과 디자인 시스템

- 색상, 글꼴 크기, 간격, 모서리, 그림자, 레이어와 상태 색을 의미 기반 토큰으로 재정의합니다.
- 버튼, 입력, 배지, 카드, 패널, 표, 빈 상태와 피드백 메시지의 공통 규칙을 만듭니다.
- 문자 기호 아이콘을 일관된 inline SVG 아이콘으로 교체합니다.
- 기존 화면 기능은 유지하면서 스냅샷 기준이 될 대표 화면을 고정합니다.

### 061. 앱 셸과 반응형 내비게이션

- 사이드바, 상단 헤더와 콘텐츠 최대 폭을 다시 설계합니다.
- 화면별 행동만 Context Header에 노출하고 전역 새로고침은 보조 행동으로 이동합니다.
- 1180px 최소 폭을 제거하고 데스크톱, 태블릿과 모바일 내비게이션을 구현합니다.
- 현재 위치, 키보드 포커스와 모바일 메뉴 상태를 명확히 표시합니다.

### 062. 스케줄 Control Tower 재설계

- 최신 실행 상태와 대표 KPI의 정보 위계를 정리하고 중복 지표를 줄입니다.
- 실행 전 빈 상태에는 필요한 준비 항목과 다음 행동을 제공합니다.
- 실행 중·성공·실패 상태를 배너, 진행 표시와 복구 행동으로 구분합니다.
- 오더 흐름과 병목 진단은 판단에 필요한 요약을 먼저 보여주고 상세 탐색으로 연결합니다.

### 063. 간트와 계획 탐색 경험

- 필터 도구 모음을 검색, 설비, 기간과 초기화 행동으로 재구성합니다.
- 설비 열과 시간 축의 고정, 작업 색상과 지연·Changeover 범례를 개선합니다.
- 작업 선택 시 오더, 공정, 설비, 시작·종료, 지연 이유를 상세 패널로 보여줍니다.
- 좁은 화면에서는 가로 탐색을 유지하되 현재 범위와 조작 방법을 명확하게 안내합니다.

### 064. 생산오더와 마스터 데이터 작업 흐름

- 표의 밀도, 정렬, 상태 배지, 행 행동과 페이지네이션을 통일합니다.
- 검색 결과 수, 활성 필터와 필터 초기화를 눈에 보이게 제공합니다.
- 9개 dialog의 제목, 설명, 필드 그룹, 검증 오류와 저장 상태를 공통 패턴으로 정리합니다.
- 데이터가 없을 때 등록 순서와 학습 샘플 생성으로 연결되는 빈 상태를 제공합니다.

### 065. APS 사용자 가이드 재설계

- 과정 목차와 현재 진도를 고정된 학습 내비게이션으로 제공합니다.
- 개념 설명의 본문 폭과 타이포그래피를 읽기 좋게 조정합니다.
- 시나리오 카드는 학습 목표, 예상 시간, 선행 과정, 완료 상태와 시작 행동을 중심으로 단순화합니다.
- 실습 전 예상 → 실행 → 관찰 → 결과 해설을 하나의 반복 가능한 학습 패턴으로 통일합니다.

### 066. 비동기 상태, 접근성과 마이크로 인터랙션

- 초기 로딩과 부분 갱신에 skeleton 또는 영역별 진행 상태를 제공합니다.
- API 오류를 일회성 toast에만 의존하지 않고 해당 화면에서 복구할 수 있게 합니다.
- 포커스 이동, dialog 키보드 조작, ARIA 이름, 대비와 `prefers-reduced-motion`을 검증합니다.
- hover, pressed, loading과 disabled 상태에 짧고 일관된 전환 효과를 적용합니다.

### 067. 통합 시각 검증과 문서 현행화

- 1440px, 1024px, 390px 대표 viewport에서 네 화면과 주요 dialog를 검증합니다.
- 빈 데이터, 샘플 데이터, 대량 데이터, 실행 중과 API 오류 상태를 점검합니다.
- 기존 Java 및 정적 리소스 테스트를 실행하고 핵심 UI 계약 테스트를 보강합니다.
- README, UI 문서, 학습 가이드와 화면 캡처를 최종 동작에 맞게 갱신합니다.

## 완료 기준

- 390px 이상에서 페이지 전체가 강제로 1180px 폭을 요구하지 않습니다.
- 본문, 표, 버튼과 입력 요소의 글자가 확대 없이 읽을 수 있는 크기와 대비를 갖습니다.
- 각 화면에서 대표 행동과 현재 상태를 5초 안에 찾을 수 있습니다.
- 키보드만으로 내비게이션, 필터, 표 행동과 dialog를 사용할 수 있습니다.
- 빈 상태와 오류 상태가 원인, 현재 영향과 다음 행동을 함께 안내합니다.
- 스케줄 보드, 생산오더, 마스터 데이터와 가이드가 하나의 제품처럼 보입니다.
- 각 작업은 하나의 독립 커밋으로 구현·검증하고 즉시 `main`에 push합니다.

## 이번 범위에서 제외

- React, Vue 등 프레임워크로의 전면 재작성
- Node.js 기반 번들러와 별도 프론트엔드 배포 파이프라인
- 서버 API와 APS 스케줄링 도메인의 불필요한 변경
- 애니메이션 자체를 위한 복잡한 시각 효과
- 디자인만을 위한 외부 SaaS 또는 런타임 CDN 의존성

## 최종 검증 결과

- 공통 디자인 토큰, inline SVG 아이콘과 읽기 크기를 적용했습니다.
- 데스크톱 사이드바와 980px 이하 접이식 내비게이션을 구현했습니다.
- 실행 요약, 첫 계획 체크리스트, KPI, 간트 상세 탐색과 데이터 화면을 재설계했습니다.
- 사용자 가이드의 학습 목차, 읽기 크기와 실습 메타를 개선했습니다.
- 지속형 오류 복구, 로딩 상태, dialog 접근성과 감소 모션을 지원합니다.
- 1440px, 1024px, 390px에서 네 화면의 페이지 수평 오버플로가 없습니다.
- 390px에서 Routing과 생산오더 dialog가 viewport 안에서 동작합니다.
- 표준 테스트 305개 중 286개 통과, 실패 0개, 조건부 19개 스킵을 확인했습니다.
- 별도 `performanceTest` 2개가 통과했습니다.
